Database

  • Database are the container for data. They are used to store, manage, and retrieve data efficiently.
  • Databases can be classified into different types based on their structure and usage, such as relational databases, NoSQL databases, and in-memory databases. Each type has its own advantages and is suitable for different use cases.
  • Querying databases involves using a query language, such as SQL for relational databases, to perform operations like inserting, updating, deleting, and retrieving data. Proper database design and indexing are crucial for optimizing performance and ensuring data integrity.

SQL

SQL (Structured Query Language) is a standard programming language used for managing and manipulating relational databases. It provides a set of commands and syntax for performing various operations on databases, such as creating tables, inserting data, querying data, updating records, and deleting records.

SQL is widely used in database management systems (DBMS) and is essential for developers, data analysts, and database administrators to interact.

SQL Queries

  1. Query for creating a database (named "mydb"): 
    CREATE DATABASE mydb;
  2. Query for making a database schema default: 
    USE mydb;
  3. Query for creating a database table (named "users") with columns for id, name, email, and created_at: 
    CREATE TABLE users (
            id INT PRIMARY KEY,
            name VARCHAR(100),
            email VARCHAR(100) UNIQUE,
            created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
            );
  4. Query for retrieving all records from the "users" table: 
    SELECT * FROM users;
  5. Query for retrieving some records from the "users" table: 
    SELECT id , email FROM users;

Data Types

  1. INT: Used to store integer values.
  2. VARCHAR: Used to store variable-length character strings. VARCHAR(100) means it can store up to 100 characters.
  3. TEXT: Used to store large amounts of text data.
  4. ENUM: A string object with a value chosen from a predefined list of values.
  5. DATE: Used to store date values.
  6. TIMESTAMP: Used to store date and time values.
  7. BOOLEAN: Used to store true/false values.

Constraints

  1. PRIMARY KEY: Uniquely identifies each record/row in a table.
  2. FOREIGN KEY: Establishes a relationship between two tables.
  3. UNIQUE: Ensures that all values in a column are unique.
  4. NOT NULL: Ensures that a column cannot have a NULL value.
  5. CHECK: Ensures that all values in a column satisfy a specific condition.
  6. DEFAULT: Sets a default value for a column when no value is specified.
  7. AUTO_INCREMENT: automatically generates a unique number for each row.

Working with tables in MySQL

Selecting All the Records

To select all the records from a table, you can use the SELECT statement with the * wildcard. For example, to select all records from a table named "users", you would use the following query: 

SELECT * FROM users;

Selecting Specific Columns

If you want to select specific columns from a table, you can specify the column names in the SELECT statement. For example, to select only the "id" and "email" columns from the "Users" table use query: 

SELECT id, email FROM users;

Renaming a table

To rename a table in MySQL, you can use the RENAME TABLE statement. For example, to rename a table named "users" to "user_profiles", you would use the following query: 

RENAME TABLE users TO user_profiles;

Altering a table

  1. To add a new column to a table, you can use the ALTER TABLE statement with the ADD COLUMN clause. For example, to add a new column named "age" of type INT to a table named "users", you would use the following query: 
    ALTER TABLE users ADD COLUMN age INT;

    ALTER TABLE users ADD COLUMN is_active BOOLEAN DEFAULT TRUE;
    ```
  2. To drop (remove) a column from a table, you can use the ALTER TABLE statement with the DROP COLUMN clause. For example, to remove the "age" column from the "users" table, you would use the following query: 
    ALTER TABLE users DROP COLUMN age;

    ALTER TABLE users DROP COLUMN is_active;
    ```
  3. To modify an existing column in a table, you can use the ALTER TABLE statement with the MODIFY COLUMN clause. For example, to change the data type of the "age" column in the "users" table from INT to VARCHAR(3), you would use the following query: 
    ALTER TABLE users MODIFY COLUMN age VARCHAR(3);

Positioning

  1. To swap the position of two columns in a table, For example, to move the "email" column to be the first column in the "users" table, you would use the following query: 
    ALTER TABLE users MODIFY COLUMN email VARCHAR(100) FIRST;
  2. To move the "email" column to be the column after the 'id' column in the "users" table, you would use the following query (need to specify the data type of the column when using MODIFY COLUMN) : 
    ALTER TABLE users MODIFY COLUMN email VARCHAR(100) AFTER id;

In MySQL, you can specify the position of a new column when adding it to a table using the FIRST or AFTER keywords in the ALTER TABLE statement. By default, new columns are added to the end of the table.

  1. To add a new column at the beginning of a table, you can use the FIRST keyword. For example, to add a new column named "created_at" of type TIMESTAMP at the beginning of a table named "users", you would use the following query: 
    ALTER TABLE users ADD COLUMN created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP FIRST;
  2. To add a new column after an existing column, you can use the AFTER keyword. For example, to add a new column named "last_login" of type TIMESTAMP after the "email" column in the "users" table, you would use the following query: 
    ALTER TABLE users ADD COLUMN last_login TIMESTAMP AFTER email;

Querying Data

Querying data in a database involves retrieving specific information from one or more tables based on certain criteria. SQL provides various clauses and operators to filter, sort, and aggregate data. Common clauses used in querying data include WHERE, ORDER BY, GROUP BY, and HAVING.

Filtering Data with WHERE Clause

  • The WHERE clause is used to filter records based on specified conditions. For example, to retrieve all users with the name "John" from the "users" table, you would use the following query: 
    SELECT * FROM users WHERE name = 'John';

  • For example, to retrieve all users where the "id" is greater than 10 from the "users" table, you would use the following query: 
    SELECT * FROM users WHERE id > 10;

  • For example, to retrieve all users who are not "MALE" from the "users" table, you would use the following query: 
    SELECT * FROM users WHERE gender != 'MALE';
  • To retrieve all users of gender "MALE" & "FEMALE" from the "users" table, you would use the following query: 
    SELECT * FROM users WHERE gender IN ('Male', 'Female');

Filtering Data with BETWEEN Clause

  • To retrieve all users with the date of birth between '1990-01-01' and '2000-12-31' from the "users" table, you would use the following query: 
    SELECT * FROM users WHERE date_of_birth BETWEEN '1990-01-01' AND '2000-12-31';

Filtering Data with AND/OR Clause

  • To retrieve all users that are "FEMALE" with "SALARY" above "70000" from the "users" table, you would use the following query: 
    SELECT * FROM users WHERE gender = 'FEMALE' AND salary > 70000;

  • To retrieve all users that are either "MALE" or have "SALARY" more than "65000" from the "users" table, you would use the following query: 
    SELECT * FROM users WHERE gender = 'MALE' OR salary > 65000;

Filtering Data with ORDER BY Clause

  • To retrieve all users that are either "MALE" or have "SALARY" more than "65000" in ascending order of their Date of Birth from the "users" table, you would use the following query: 
    SELECT * FROM users WHERE gender = 'MALE' OR salary > 65000 ORDER BY date_of_birth ASC;

Filtering Data with LIMIT Clause

  • To retrieve "5 top" users that are either "MALE" or have "SALARY" more than "65000" in ascending order of their Date of Birth from the "users" table , you would use the following query: 
    SELECT * FROM users WHERE gender = 'MALE' OR salary > 65000 ORDER BY date_of_birth ASC LIMIT 5;

Functions in SQL

SQL provides various built-in functions to perform operations on data. These functions can be used in SELECT, WHERE, and ORDER BY clauses to manipulate and retrieve data in a more efficient manner.

COUNT Function

  • To get a count of all users from the "users" table, you would use the following query: 
    SELECT COUNT(*) FROM users;

  • To get a count of all MALE users from the "users" table, you would use the following query: 
    SELECT COUNT(*) FROM users WHERE gender = 'MALE';

MIN() MAX() Function

  • To get the minimum salary from the "users" table, you would use the following query: 
    SELECT MIN(salary) FROM users;
  • To get the minimum salary from the "users" table in the name Min_Salary, you would use the following query: 
    SELECT MIN(salary) FROM users AS Min_Salary;
  • To get the maximum salary from the "users" table, you would use the following query: 
    SELECT MAX(salary) FROM users;/

SUM Function

  1. To get the sum of all salaries from the "users" table, you would use the following query: 
       SELECT SUM(salary) FROM users;
  2. To get the sum of all salaries from the "users" table gender wise, you would use the following query: 
     SELECT SUM(salary) FROM users GROUP BY gender;
  3. To get the sum of all salaries from the "users" table gender wise, with the group name, you would use the following query: 
      SELECT gender, SUM(salary) FROM users GROUP BY gender;

Primary Key and UNIQUE Constraints

Primary Key

A primary key is a column or a combination of columns that uniquely identifies each row in a table.
If you want to identify a record uniquely, you need to have a column that has a unique element, on basis of which you can seperate a user/value. A table can have only one primary key, and it cannot contain NULL values. Hence we use Primary Key constraint with that element to identify a record uniquely.

Some characteristics of Primary Key:
  • Is always Unique
  • Cannot be Null
  • Each table can have only one Primary Key

UNIQUE Constraint

A UNIQUE constraint ensures that all values in a column are different.

How is PRIMARY KEY different from UNIQUE Constraint?

Both PRIMARY KEY and UNIQUE constraints enforce uniqueness in a column or a set of columns. However, there are some differences between them:

  • A table can have only one PRIMARY KEY, but it can have multiple UNIQUE constraints.
  • PRIMARY KEY columns cannot contain NULL values, while UNIQUE columns can contain NULL values (but only one NULL value is allowed).
  • PRIMARY KEY is used to uniquely identify each row in a table, while UNIQUE is used to ensure that values in a column are unique.
  • It is recommended to use a PRIMARY KEY in order to uniquely identify rows, while UNIQUE may or may not be used
  • It cannot be easily dropped, this may even fail if it is used elsewhere, while UNIQUE may be dropped more easily

Auto Increment Constraint

The auto increment constraint is used to automatically generate a unique number for each row in a table. It is often used for primary key columns to ensure that each row has a unique identifier. When a new row is inserted into the table, the auto increment column will automatically be assigned the next available value, without the need for manual input.

To create an auto increment column, you can use the AUTO_INCREMENT keyword in the CREATE TABLE statement. For example, to create a table named "users" with an auto increment column named "id", you would use the following query:

CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100) UNIQUE;)

In this example, the "id" column is defined as an auto increment column, and it will automatically generate a unique value for each new row inserted into the "users" table.

We can also change the starting value of the auto increment column using the ALTER TABLE statement.

ALTER TABLE users AUTO_INCREMENT = 1000;

Foreign Key Constraint

A foreign key is a column or a set of columns in one table that refers to the primary key in another table. It establishes a relationship between two tables and ensures referential integrity.
